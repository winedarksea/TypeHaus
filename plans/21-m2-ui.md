# M2 — UI: Editor Architecture, 3D Panel, Presentation

**Purpose:** the local web app half of M2 — architecture, core editing interactions, the
assembly inspector, and the 3D panel with the Nordic preset. The macros, driven dimensions,
drafting commands, and intelligence features are (→ 21b).

## Stack & architecture

- **Stack:** React + TypeScript + Vite; **SVG** editor (hundreds of elements — DOM
  hit-testing, crisp linework, native text beat canvas complexity; revisit only if profiling
  says so). State via zustand. **The server owns all geometry math**; the UI is a view +
  patch emitter over `model.json` (→ 20 §FastAPI server).
- **`EngineClient` boundary (day one, #15):** all engine access goes through one typed TS
  interface — `getModel() / getChecks() / patchPlan(ops) / build(opts) / getArtifact(kind) /
  events()` — with the M2 implementation `HttpEngineClient` (fetch + WebSocket). No component
  touches the network directly. This is deliberately the seam that lets a
  `PyodideEngineClient` (in-browser engine in a Web Worker) slot in for the offline PWA
  (→ 40) without touching any editor code.
- **Editing loop:** UI renders the server's `model.json` (resolved geometry + provenance +
  `editable` flags) → user edits → element-level **patch ops** → server applies via libcst
  writeback → rebuild → WebSocket push → re-render. Target **< 2 s** round trip.
- **Touch-first, tablet-class (not smartphone, #14):** the editor targets iPad-landscape
  viewports and up. Tap = select; oversized drag handles and snap radii (scaled with zoom;
  ≥ 44 px hit targets); two-finger pan / pinch zoom; long-press = context menu; **no
  hover-only actions or menus** — but hover **is** used for passive feedback where it exists
  (snap-target dots on nodes/midpoints, pre-highlight before click: near-mandatory ergonomics
  in 2D drafting); touch gets the equivalent feedback *during* the drag (snap indicators
  render while dragging, before commit). On-screen ft-in keypad for dimension entry. Keyboard
  shortcuts remain as desktop accelerators. The M2 Playwright suite runs the drawing script
  in a touch-emulated tablet viewport as well as desktop (→ 02 §Verification).

## Core editing interactions

- **Wall-drawing UX that guarantees closure:** draw = click node → click node; cursor snaps
  to existing nodes/endpoints/axis alignments/grid. Every new wall gets the
  preferences-default assembly immediately, flagged with a "confirm assembly" badge —
  *unconfigured is a visible state, never a silent one*. Open-ended nodes render as red
  pulsing markers driven by the integrity checker (same findings as `haus check`).
- **Rooms:** derived faces render tinted; click-to-claim opens name/ceiling/occupancy editor;
  soffits = draw polygon + set drop (storey-level, may span rooms — #40).
- **Openings:** drag door/window from palette onto a wall; snaps to dimension increments;
  type picker from library.
- **Assembly picker + inspector:** sidebar listing plan + `library/` assemblies (variants
  grouped under their base) with live computed R-value; selecting one opens the **assembly
  inspector panel** — the section card (→ 12 §Assembly card) rendered live from `model.json`
  card geometry: layers to scale, control-layer badges, R-value rollup, core/lining split.
  This is the UI's read affordance for assemblies; editing them remains code/agent work.
  Swap scopes — this wall / contiguous run (auto-split at the boundary) / all walls with this
  assembly — with the ghost preview (→ 21b §Swap preview).
- **Conflict banner (#30):** stale-source detection surfaces as a canvas banner with an
  element-level summary of what changed on disk and **reload** as the only mutation path
  (→ 20 §Write safety).

## 3D panel

`@thatopen/components` + `web-ifc` behind a **`ModelViewer` interface** (pin versions),
loading the fresh **framed-LOD** IFC; element click cross-highlights the 2D plan and shows
`file:line` provenance (jump-to-VSCode affordance). Fallbacks in order (risk 4, → 02 §Risk
register): (a) raw web-ifc + three.js; (b) glTF emitted from `ResolvedModel` rendered with
plain three.js; (c) "open in Bonsai" (UI fully usable 2D-only).

## Presentation preset — "Nordic" by default (#24)

Pretty output with zero user work and low code complexity, by concentrating all appearance in
one place:

- **One palette module** — a single material→color map (muted Nordic range: warm wood tones
  for framing, off-whites for gyp, muted mineral blue-greens for insulation, soft grays for
  concrete) defined once and consumed by **all three surfaces**: IFC surface styles (3D), SVG
  editor fills, and 2D detail/plan hatches (superseding `MATERIAL_COLORS` in
  `detail_utils.py`) — plus the assembly section card (→ 12). The 2D plan, the 3D view, and
  the printed details always agree on what wood looks like.
- **3D panel rendering, three cheap standard passes** on the ThatOpen/three.js scene: soft
  neutral environment lighting, an **SSAO pass** (three.js `N8AO`/`SAOPass` — postprocessing
  config, not custom shaders), and **edge/outline rendering** (`EdgesGeometry` at a
  crease-angle threshold — reads as clean architectural linework and makes stud arrays
  legible). All three are configuration on the existing pipeline; they survive the risk-4
  fallback paths including the glTF route, since they attach to the three.js scene, not to
  IFC parsing.
- **Instancing for framing:** studs/joists at framed LOD render as `InstancedMesh` per member
  profile (hundreds of identical boxes → a handful of draw calls), which is what keeps the
  signature framing view fast on a tablet. `model.json` ships members as instanced-primitive
  refs for the same reason (→ 20).
- Preset is the default; a plain "schematic" mode (flat colors, no passes) remains for
  low-power devices.

## Workpackages

- **WP2.3 React app shell.** Vite + zustand + `model.json` rendering (walls, nodes, rooms,
  openings), provenance display, editable/read-only flags (params-generated elements show
  the "edit in code" badge); all engine access through `EngineClient` with
  `HttpEngineClient`. *Done when:* the demo plan renders faithfully from `model.json` alone.
- **WP2.4 Editor interactions.** Node-snap wall drawing, default-assembly badge, open-end
  markers, assembly picker + **inspector panel** (live R-value + section card), opening
  drag-drop, room claiming + ceiling/soffit editor; **framed floorplan rendering** (real stud
  cuts + layer hatching from the → 11 solve, with the schematic toggle); touch-first per
  above (tap select, pinch pan/zoom, long-press menus, oversized handles, ft-in keypad);
  extents & dimensions HUD (→ 21b §HUD); **assembly swap flows with ghost preview**
  (→ 21b §Swap preview). *Done when:* the Playwright drawing script passes on desktop and
  tablet-emulated viewports.
- **WP2.5 3D panel.** ThatOpen/web-ifc embed behind `ModelViewer` (pinned; fallback = plain
  web-ifc + three.js mesh dump); loads the framed-LOD IFC; **Nordic preset** (palette module,
  SSAO + edge passes, `InstancedMesh` framing, schematic fallback mode). *Done when:*
  clicking a stud in 3D highlights its parent wall in 2D and shows its `file:line`.

## Risks owned

- **Risk 4 — ThatOpen/web-ifc churn.** Mitigation pattern: the `ModelViewer` interface is
  the isolation seam; versions pinned; the three fallbacks are ordered and the Nordic passes
  attach to the three.js scene so they survive all of them.
